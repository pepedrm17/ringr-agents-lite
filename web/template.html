Qué pide la prueba

Dos agentes, DebtAgent y AssistanceAgent. En cada turno, handle_turn hace cuatro cosas:

1

Responde

Con ConversationModel.answer_user.

2

Extrae datos

Con ParserModel.parse_data, que devuelve un dict.

3

Decide

Valida los datos y comprueba si hay que actuar.

4

Ejecuta

Construye la request con el Bearer token y los datos como cabeceras. No se envía.

Reglas de negocio y diseño

DuplicadosCada agente registra su acción como mucho una vez por conversación.
Fechas«el 4» es este mes si ese día no ha pasado (hoy cuenta); si ya pasó, el mes siguiente; si ese mes no tiene ese día, el último día del mes.
Fecha pasadaUna fecha completa anterior a hoy no se registra.
ImporteNúmero con «€» o «euros», mayor que cero.
SolicitudesUn mensaje que pide algo; «quiero saber…» es una duda y «no quiero…» rechaza.
Fallos HTTPSolo 200 es éxito; cualquier otro código se reintenta en el siguiente turno.

Diseño: una clase base Agent fija el orden del turno y la regla de duplicados; cada agente solo define su endpoint y decide.
